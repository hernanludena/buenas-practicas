# Desarrollo incremental y programación con agentes

| Nombre | Descripción breve |
|---|---|
| Backlog por fases | Dividir el objetivo en fases e historias pequeñas con dependencias y criterios de aceptación verificables. |
| Especificación viva | Mantener alcance, arquitectura y contratos actualizados por incrementos; desarrollo guiado por especificación no exige waterfall. |
| Agent rules | Escribir reglas de arquitectura, capas, seguridad, pruebas y estilo en AGENTS.md o equivalente del repo. |
| Una HU por ciclo | Planificar, implementar una historia, revisar contra criterios, ejecutar verificaciones acordadas y recién después avanzar. |
| Gate entre fases | Comparar implementación con especificación, pruebas, migraciones y arquitectura antes de cerrar cada fase. |
| AI pair programming | Usar copiloto para explorar/implementar; revisar diffs, validar decisiones y no aceptar código solo porque compila. |
| Voz y lectura de repos | Dictado y lectura por voz aceleran exploración/comandos; verificar la transcripción y revisar las acciones antes de ejecutarlas. |
| Calidad sostenible | Preferir entregas pequeñas y mantenibles; no sacrificar límites, pruebas y observabilidad por terminar más rápido. |
